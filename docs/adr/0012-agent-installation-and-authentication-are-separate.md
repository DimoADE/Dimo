# Agent 安装与认证是独立生命周期

Agent 的安装状态、认证状态、启用状态与会话可用性彼此独立，不能混用为单一的“已配置”或“已启用”布尔值。

## Decision

- **安装不以登录为前提**：本地 Runtime（独立原生引擎或 ACP 适配器）完成安装、版本/路径/完整性校验及初始化握手后，该 Agent 即进入已安装状态。需要认证但当前未登录或缺少凭据的 Agent 进入待认证状态，继续在 Agent 设置中展示；只有同时满足安装、认证与必需配置条件的就绪 Agent 才能用于创建新会话。
- **认证失败不回滚安装**：认证未完成、过期或用户暂缓登录不会撤销或删除已经验证通过的安装。
- **非交互安装与显式交互登录分离**：“添加并安装”只执行非交互式的下载、校验、安装与初始化握手，绝不在安装期间或后台探测中自动触发浏览器授权、设备码或 CLI 登录。用户可在设置页明确触发 Built-in Agent Profile 白名单中的官方账号流程（见 [ADR-0037](0037-built-in-agent-account-actions-and-codeg-parity.md)），交互过程由官方 CLI 或页面持有。
- **原生配置明确编辑**：Built-in Agent Profile 已适配的原生 Runtime 配置字段（API URL、API Key、模型、推理强度与常用选项等）由用户在详情页明确编辑；Dimo 不自动写入默认凭据，也不把临时会话选项误写成持久原生配置。
- **只读检查与显式写操作分离**：“立即检查”、进入设置页、应用启动与后台探测始终是只读操作，不得自动下载或修复。只有用户明确触发“修复”、安装、更新或在设置页显式启用 Agent 时才执行写操作（显式启用成功后会立即预检查并按结果推进安装/修复/更新，但停用或未登录均不触发重装）。
- **必需能力与可选能力分层降级**：Runtime 完整性、必需组件或握手失败时进入需要修复且禁止创建会话；必需认证无法确认时保持已安装但不可就绪；订阅可见性、账户详情等可选管理能力探测失败时 Agent 保持就绪，仅对应能力进入降级状态并提供诊断与重试。“未提供该能力”与“已提供但探测失败”必须明确区分。

## Consequences

- 用户可以先安装并检查所有 Agent 的环境健康度，再按需完成单个 Agent 的登录或供应商配置。
- 设置页与会话创建入口的提示始终准确反映具体阻塞维度（缺失安装、需修复、待认证或已禁用）。
